# 10. 先扩写再执行（流程门禁）

## ① 何时触发（三档分流，不一刀切）

- **触发扩写**：新增功能、跨文件改动、改公共模块、需求含「优化」「重构」「加个 XX」等模糊词、涉及删除或迁移。
- **不触发**：单行改错别字、改注释、只读查询、用户已给出完整规格。
- **拿不准** → 问一句：「要我出规格书再动手，还是直接改？」

## ② 五步流程

1. **拆意图**   产物是脚本 / 模块 / 函数 / 一次性命令？形态决定规格深度。
2. **验空白**   技术栈 / 边界说不说？不确定就举例问，不沉默写死。
3. **六段扩写** 缺的段写「不适用 + 原因」，禁止用「合理处理各种异常」填空。
4. **输出**     整块 Markdown 代码块，可一键复制。
5. **等确认**   用户点头才写代码；不点头只停在规格。

执行位置：`AGENT_RULES.md` §1 第 2 步「列计划」之前；满足本规则后再走 `TodoWrite`。

## ③ 六段规格模板（AI 直接套用，原样照抄）

```markdown
# Role & Context
# Tech Stack
# Detailed Requirements
# Edge Cases & Failure Recovery（必须是「具体场景 → 具体行为」的表）
# Code Quality & Style
# Test & Verification（必须含 ≥1 个故意失败的反证用例）
```

## ⑤ 输出格式

- 规格必须在一个 `markdown` 代码块内，不拆散到正文。
- 末尾固定一行：`👉 回「开工」，我就按这份规格写实现`。
- 规格全文 ≤ 200 行；超了说明在灌废话。

## ⑥ 自检清单（8 条，交付规格前逐项过）

1. 六段齐全？
2. 技术栈给了默认值 + 换栈方式？
3. 边界是具体行为不是「合理处理」？
4. 有「不要做」段？
5. 测试含故意失败用例？
6. 验收判据落在产物（文件存在 / 字节数 / grep 命中），不是 exit code？
7. 无凭据 / 无内网真实地址？
8. 整份在一个代码块里？

整条通过后再问「要不要按此开工」；任一项不通过先回去补段。

## Edge Cases & Failure Recovery（本规则自身的兜底）

| 场景 | 期望行为 |
| --- | --- |
| `.trae/rules/` 目录不存在 | 先 `mkdir -p .trae/rules` 再写文件，不报错 |
| 目标文件名已存在 | 停止覆盖，改为读取现有内容 + 输出 diff 提议，等用户裁决 |
| `AGENT_RULES.md §1` 与本规则冲突 | 不擅自改任何一方，输出「冲突清单 + 两条候选裁决」交用户 |
| frontmatter 写坏（YAML 不合法） | Trae 会静默不加载 → 写完后必须回读校验 YAML 可解析 |
| 用户明确说「别走流程，直接改」 | 服从用户实时指令，但回复首行注明「已跳过规格门禁」 |
| 权限不足 / 路径不可写 | 打印完整目标路径 + 需要的权限，不假装已创建 |

日志：每一步落盘后打印 `✅ 已写入 <绝对路径>（N 字节）`；失败打印 `❌ <路径>：<原因>`。

## Code Quality & Style

- 规则文件用中文书写（与 `AGENT_RULES.md` 一致），专有名词保留英文。
- 每个 `.md` 首行为 `# <标题>`，其后 `---` 分隔，再进正文。
- 规则条目用「可判定的祈使句」：「禁止 X」「必须先 Y」，不用「尽量」「适当」。
- 代码示例用带语言标注的围栏；行内路径用反引号。
- 单条规则 ≤ 3 行，超了就拆条。

## Test & Verification

- **YAML 可解析**：
  `python3 -c "import yaml,io;d=open('.trae/rules/10-先扩写再执行.md',encoding='utf-8').read().split('---')[1];print(yaml.safe_load(d))"`
  → 必须输出含 `alwaysApply: True` 的 dict。
- **Trae 真的读到了**：打开 Trae → 设置 > 规则与记忆，确认列表里出现该规则且生效方式显示「始终生效」。
- **反证（必做）**：在 Trae 对话里输入一句模糊需求「优化一下项目」，观察 AI 是否先出六段规格而不是直接改文件。
  若直接开始改代码 → 规则未生效，回到第 ② 步查 frontmatter。
- **无副作用核验**：`git status --porcelain` 必须只出现 `.trae/rules/` 和 `.cursorrules` 两项。
- **验收判据**：不看「命令没报错」，看三个文件事实 —— 新文件存在、字节数 > 500、`grep -c alwaysApply = 1`。
