# v2.0.9 Release Notes

> Release date: 2026-09-04
> Tag: `v2.0.9`
> Source of truth: [docs/VERSION_MANAGEMENT.md](../docs/VERSION_MANAGEMENT.md)
> Previous: [release_notes/v2.0.8.md](./v2.0.8.md)

This is a **capability release**. It closes out the v2.0 slim refactor started in
v2.0.7 and lands the `harness` evaluation runner + the GitHub release CI / merge-label
workflows that were unblocked by I-7 (PAT scope) in v2.0.8. No business API
breaks; all `v2.0.x` consumers stay compatible.

## Highlights

### 1. v2.0 slim — slim Agent runtime (`ai_agent/v2_slim/`)

A side-by-side slim runtime that replaces five heavyweight modules with three
merged ones. Off by default (`AIAgent_LEGACY=false`); flip `AIAgent_LEGACY=true`
to fall back to the v1 implementations.

| Old module | v2.0 slim replacement |
|---|---|
| `tools.py` (30+ tools) + `mcp_tools.py` | `v2_slim/tools_v2.py` — 6 composite `@tool` with `subcommand: Literal[...]` |
| `memory_store.py` (4 memory types) + `context_manager.py` | `v2_slim/memory_store_v2.py` — dual `ShortTermContext` + `LongTermKnowledge` |
| `multi_agent.py` (5 modes) + `negotiation.py` | `v2_slim/multi_agent_v2.py` — keeps only `SEQUENTIAL` + `SUPERVISOR` |
| `permission.py` + `human_in_loop.py` | `v2_slim/approval.py` — unified `ApprovalGate` + RBAC `Policy` |
| `observability.py` + `monitor.py` + `json_log.py` | `v2_slim/telemetry.py` — single `TelemetrySink` facade |
| `ab_testing.py` / `adaptive_threshold.py` / `rate_limit.py` | frozen — `frozen("name")()` raises `NotImplementedError` |
| `distributed_bus.py` | frozen |
| `mcp_register` / `mcp_invoke` | frozen |

Migration helper: [`ai_agent/scripts/migrate_memory_v1_to_v2.py`](../ai_agent/scripts/migrate_memory_v1_to_v2.py)
folds EPISODIC/PROCEDURAL records into ShortTerm/LongTerm.

Routing entry-point: [`v2_slim/multi_agent_router.py`](../ai_agent/v2_slim/multi_agent_router.py)
respects `LEGACY_MODE` so callers don't need to branch.

### 2. Harness — Agent runtime facade (`ai_agent/harness.py`)

A thin orchestration layer that wraps `AIAgent.run()` / `run_stream()` with
configurable flags (planner / memory / observability / security / sandbox) and
emits a `Trace` (typed dataclass) per call for replay, debug, and post-mortem.

```python
from harness import Harness, HarnessConfig

cfg = HarnessConfig(
    session_id="user-42",
    sandbox="standard",
    enable_planner=False,
    enable_memory=True,
    enable_observability=True,
)
h = Harness.from_config(cfg)

reply = h.run("你好")
for chunk in h.run_stream("解释这段代码"):
    print(chunk, end="")

# Full trace to dict for replay / PR attachment
h.last_trace.to_dict()
```

Supports dependency injection (`Harness(agent=..., memory_store=..., observability=...)`)
so unit tests and multi-tenant setups can swap in mocks.

Full reference: [`ai_agent/docs/HARNESS.md`](../ai_agent/docs/HARNESS.md).

### 3. Eval Harness — repeatable regression suite (`ai_agent/harness_runner.py` + `evals/`)

A `HarnessRunner` that loads cases from JSONL, runs them through `Harness`, scores
each with pluggable scorers (`KeywordScorer`, `EmbedScorer`, `CompositeScorer`),
and writes a structured run to `evals/runs/<timestamp>/` with `cases.jsonl`,
`summary.json`, and `metrics.json`.

- CLI: `python harness_cli.py run --case-set evals/sets/smoke_v1.jsonl --out evals/runs/<ts>/`
- `--dry-run` path skips the real agent (used in CI for fast smoke)
- 9 existing runs already in `ai_agent/evals/runs/` (5 harness_dry_* +
  `harness_pr{6,8,9,11}_local` + `harness_smoke_test`)

### 4. Release CI + PR merge-label workflows (`.github/workflows/`)

Unblocks I-7 from v2.0.8 by depending on the optional `workflow` scope:

- [`.github/workflows/release.yml`](../.github/workflows/release.yml) — tag-driven
  pipeline (`v[0-9]+.[0-9]+.[0-9]+*`). Resolves version, builds `sdist` + `wheel`
  from `ai_agent/pyproject.toml`, packages a source tarball, generates release
  notes from the commit log, and calls `release_cli.py github <ver>` (gh CLI
  preferred, REST fallback) plus `release_cli.py gitee <ver> --create-release`
  when `GITEE_TOKEN` is set. Permissions: `contents: write`, `pull-requests: write`.
- [`.github/workflows/pr-merge-label.yml`](../.github/workflows/pr-merge-label.yml)
  — on `pull_request.closed` with `merged=true` and a title matching `Release` /
  `release`, applies the `release` label via `release_cli.py webhook` and posts
  a confirmation comment with the run URL.

Both workflows are committed but **not yet active** on `master` until the PAT
scope is upgraded (see Known Caveats).

## Known Caveats

- **PAT `workflow` scope still missing**: `.github/workflows/release.yml` and
  `pr-merge-label.yml` are committed locally. They will not run on `master`
  until a PAT with `workflow` scope is configured (either as `GH_TOKEN` secret
  for `workflow_dispatch`, or upgraded on the bot user). Until then, releases
  continue to be driven manually via `release_cli.py` per
  `docs/VERSION_MANAGEMENT.md §4-6`.
- **v2 slim is opt-in**: `LEGACY_MODE` defaults to `false` (slim enabled).
  Production rollouts should flip to `AIAgent_LEGACY=true` first to validate, and
  only switch over once staging probes pass for 24h.
- **`tests/legacy/` is skipped by default** under the slim profile. The 280
  legacy cases remain on disk for reference but are not in the gating suite.
- **`frozen()` decorator** raises `NotImplementedError` immediately when called
  with arguments; this is intentional (PEP 318 semantics). Tests covering the
  error shape live in `tests/test_v2_slim_fault_tolerance.py`.

## Upgrade Notes

No breaking API changes. The `v2_slim` namespace is additive; existing
imports of `tools.py`, `memory_store.py`, `multi_agent.py`, `permission.py`,
`human_in_loop.py`, `observability.py`, `monitor.py`, `json_log.py`,
`ab_testing.py`, `adaptive_threshold.py`, `rate_limit.py`, and
`distributed_bus.py` continue to work. New code should prefer the slim
entry-points when `LEGACY_MODE=false`.

To consume this release:

```bash
git fetch origin
git checkout master
git pull
pip install -e ai_agent/    # if running from source
```

No data migration is required. If you have v1 memory stores and want to
collapse them into the dual ShortTerm/LongTerm layout, run:

```bash
python ai_agent/scripts/migrate_memory_v1_to_v2.py --src ai_agent/memory.db
```
