# v2.0.10 Release Notes

> Release date: 2026-09-07
> Tag: `v2.0.10`
> Source of truth: [docs/VERSION_MANAGEMENT.md](../docs/VERSION_MANAGEMENT.md)
> Previous: [release_notes/v2.0.9.md](./v2.0.9.md)

This is a **cleanup / dead-code-removal release**. No new features, no perf
work, no bug fixes — only deletion of dead code paths that were preserved
through v2.0.9 for safety and that are now safe to remove after the v2.0.9
staging soak.

**Contains one breaking change** (see §"Breaking Changes"). Operators must
read that section before deploying.

## ⚠️ Breaking Changes

### `AIAgent_LEGACY` environment variable is now a no-op

In v2.0.9, `AIAgent_LEGACY=true` switched the runtime back to the legacy
non-slim implementation (the "fallback path"). In **v2.0.10 this switch is
removed**. The runtime is always the v2.0 slim implementation.

**Operator action required**:

```bash
# If you previously deployed with:
export AIAgent_LEGACY=true
# → Remove that line from your systemd unit / docker-compose / k8s manifest.
#   The variable is silently ignored in v2.0.10; leaving it set will NOT
#   switch back to legacy implementations because the legacy code is gone.
```

**Why this is a breaking change**:

If a deployment was relying on `AIAgent_LEGACY=true` to bypass a v2.0 slim
issue, that bypass no longer works. The legacy modules
(`v2_slim/tools_legacy.py`, `v2_slim/memory_store_legacy.py`,
`v2_slim/multi_agent_legacy.py`, `v2_slim/permission_legacy.py`,
`v2_slim/human_in_loop_legacy.py`, `v2_slim/observability_legacy.py`,
`v2_slim/negotiation_legacy.py`) have been **physically deleted**.

If you must roll back to v2.0.9 behavior:

```bash
git revert <v2.0.10-commit-sha>   # restores legacy modules + LEGACY_MODE
# or
git checkout v2.0.9 -- ai_agent/  # restore v2.0.9 runtime, then redeploy
```

**Detection**: if your monitoring watches `config.LEGACY_MODE`, note that the
variable is now a constant `False` (no longer read from env). Alert rules that
expected it to flip will need updating.

### 2. `config.LEGACY_MODE` is now a constant `False`

[`ai_agent/config.py`](../ai_agent/config.py#L226-L230):

```python
# Was (v2.0.9):
LEGACY_MODE = os.getenv("AIAgent_LEGACY", "false").lower() == "true"

# Now (v2.0.10):
LEGACY_MODE = False  # v2.10+ no longer reads AIAgent_LEGACY env var
```

The variable is preserved for backward compatibility with monitoring scripts
and test assertions, but it no longer reflects runtime state.

These were diagnostics / probes / hand-written test scripts that lived outside
the `tests/` tree and were never collected by pytest. All were unused (no
business code imported them).

**Cleanup buckets**:

| Bucket | Count | Examples |
|---|---|---|
| Top-level `_chart_*.png` / `_e2e_*.txt` / `_dataflow.py` / `_demo.txt` / `_products.json` / `_sales.csv` | 13 | snapshot artifacts from ad-hoc matplotlib / curl probes |
| Top-level `diag_*.py` | 14 | one-off LangChain chunk / SSE header / prompt-size probes |
| Top-level `_diag_*.py` | 5 | older equivalent of above (were already `.gitignore`d) |
| Top-level `test_chart_*.py` / `test_sse*.py` / `test_tools_*.py` / etc. | 15 | hand-written test scripts duplicating `tests/` functionality |
| `ai_agent/scripts/legacy_tests/` (entire directory) | 10 | pre-`tests/` migration scratch scripts |
| `scripts/add-slow-markers.py` | 1 | referenced only deleted `tests/legacy/` paths |
| `ai_agent/tests/legacy/` (entire directory) | 26 | default-skipped historical tests |

All `.gitignore` rules now cover these patterns so future one-shot scripts
won't accumulate the same way.

## Upgrade notes

For most operators, this is a drop-in replacement:

1. Pull the `v2.0.10` tag
2. Redeploy — no env-var changes required
3. Verify with `curl http://your-host:8000/api/health` and a chat round-trip

`.env`, systemd unit, k8s ConfigMap) you must remove that line. See
[Breaking Changes §](#-breaking-changes).
