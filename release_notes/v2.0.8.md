## Highlights

### Unified release CLI (`scripts/release/release_cli.py`)

Six subcommands covering the full release lifecycle:

| Subcommand | Purpose |
|---|---|
| `github X.Y.Z` | Push tag + create GitHub Release (gh CLI preferred, REST fallback) |
| `gitee X.Y.Z [--create-release]` | Mirror tags to Gitee; optional Gitee Release via Gitee OpenAPI v5 |
| `protect <branch> [--enforce-admins]` | Apply branch protection (cross-platform wrapper around `apply_branch_protection.{sh,ps1}`) |
| `cleanup [--switch-default-to-master --delete-main]` | Orphan-branch cleanup per §7.6 (one-shot atomic flow) |
| `webhook --pr-number N [--label X] [--comment Y]` | Apply side-effects to PR events (label/comment) |
| `status` | Show local tags + GitHub releases + protection state |

Implementation notes:
- 100% Python stdlib (`urllib.request`, `subprocess`, `argparse`) — no external deps
- HTTP/2 not required; works on stock Windows / Linux
- Tested with Python 3.11+

## Known Caveats

- **PAT workflow scope missing**: Workflow files (`.github/workflows/*.yml`) are
  written locally but not pushed because the current PAT lacks the `workflow`
  scope. The release CLI is fully usable without workflows — `release.yml` and
  `pr-merge-label.yml` are optional accelerators.
  See INCIDENT_REPORT I-7 for permanent fix.
- **No status checks**: master branch protection does not require CI status
  checks yet because the project has no CI workflows.
- **Single-owner payload**: master uses `required_approving_review_count=0`
  to avoid the self-merge deadlock. When a second maintainer joins, switch
  back to the multi-maintainer payload per §7.5.2.
